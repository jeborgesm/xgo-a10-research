# XGO photographic evidence catalog

This catalog establishes the evidence-handling convention for the photographic corpus preserved under `images/inbox/`.

## Corpus

- Branch audited: `research-game-list-scanning`
- Images present: **39 JPEG files**
- Source files are intentionally preserved byte-for-byte with their original UUID filenames.
- `images/inbox/` is the immutable evidence layer. Descriptive names, classifications, crops, or annotations should be added separately rather than replacing originals.

## Evidence rules

For every photograph used in the investigation, record:

1. **Observable evidence** — only what can be directly seen in the image.
2. **Interpretation** — what the observation may imply about XGO hardware, firmware, UI, runtime behavior, controls, storage, emulator integration, or family lineage.
3. **Confidence** — confirmed / strong / tentative.
4. **Cross-reference** — the code, binary, runtime experiment, or family-firmware finding that independently supports or contradicts the interpretation.

A photograph by itself must not turn an inference into a confirmed architectural fact.

## Classification status

The manifest is complete. Semantic classification is deliberately **not guessed from filenames**. Classification should be filled only after the corresponding pixels have been inspected. This keeps the repository's evidence standard consistent with the rest of XGO Archeology: observed facts first, interpretation second.

Useful categories for the second pass:

- enclosure / external hardware
- PCB / internal hardware
- SoC, RAM, flash, power, audio, display, or connector detail
- controls / button matrix
- boot / splash / stock UI
- game-list / favorites / package artwork
- emulator runtime / pause menu / mapper / audio OSD
- storage / filesystem evidence
- family-device comparison
- experiment / modification / failure state
- duplicate or alternate angle

## Relationship to current game-list work

Photographs showing the stock game list, Favorites, package thumbnails, the SNES controller-test package, or the XGO import test are particularly valuable. They can serve as visual runtime corroboration for the list-record and `.zxx` wrapper archaeology, but the binary/runtime experiments remain the authoritative source for format claims.
