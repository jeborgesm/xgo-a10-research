## Exact wrapper boundary

XGO `Foldername.ini` configures thumbnail size as 144 x 208.

The normal game launcher computes preview bytes dynamically as:

`thumbnail_width * thumbnail_height * 2`

from frontend globals before calling `run_game`.

On the captured card:

`144 * 208 * 2 = 59,904 = 0xEA00`

At exact file offset `0xEA00`, `Test.zsf` begins with:

`WQW\x03`

Therefore the package is exactly:

```text
0x0000 .. 0xE9FF   144x208 RGB565 thumbnail, 59,904 bytes
0xEA00 .. EOF      WQW-obfuscated ZIP archive
```

## Payload contents

After de-obfuscation with only the WQW signature/filename rules, Python's standard ZIP parser opens the payload successfully.

`手柄测试.sfc`

ROM SHA-256:

`76e60393139669b25c5a82247c3fbbc6f2a9715049532b2d14991adbec60ac9b`

This proves WQW is not a custom compression format. It is a lightly obfuscated standard ZIP container.

## Exact WQW transform

The transform is:

```text
ZIP local header signature
  PK 03 04  ->  WQW 03

ZIP central-directory signature
  PK 01 02  ->  WQW 02

ZIP end-of-central-directory signature
  PK 05 06  ->  WQW 01

stored filename bytes in local and central records
  byte ^= 0xE5

compressed payload bytes
  unchanged

extra fields/comments
  unchanged
```

Family tooling independently implements the same decode rule, but the XGO result above was verified directly from captured XGO bytes.

## Import implication

A complete polished built-in wrapper can be generated deterministically from:

- raw ROM;
- 144x208 cover image converted to RGB565;
- ordinary single-file ZIP/DEFLATE container;
- trivial WQW transform;
- concatenation of thumbnail + WQW archive.

No proprietary compressor or Windows-only packaging component is required.

## On-device feasibility

The difficult part of a fully on-device `Import Game` flow is no longer container generation.

The remaining work is:

- source image decoding/resizing to 144x208;
- RGB888/RGBA -> RGB565 conversion;
- ZIP/DEFLATE creation or reuse of an existing compressed ROM file;
- filesystem-safe wrapper write;
- stable catalog append.

Stock XGO firmware contains JPEG/PNG media-decoder strings (`image/jpeg`, `image/png`, JPEG decoder diagnostics), so reuse of an existing decoder remains plausible but not yet proven as a convenient still-image API.

## Practical staged design

Stage A — `Refresh Games`: scan already-packaged `.zxx` files and stable-append missing entries.

Stage B — `Import Prepared Game`: accept a raw ROM plus a preconverted 144x208 RGB565 cover and build the wrapper entirely on-device.

Stage C — `Import Game`: accept normal PNG/JPEG artwork, decode/resize/convert it on-device, build the WQW wrapper, then catalog it.

No hardware artifact was generated by this finding.
