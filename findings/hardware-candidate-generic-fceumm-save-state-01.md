# Hardware candidate: generic FCEUmm save-state adapter 01

Status: **CI/audit clean; awaiting hardware validation**.

## Purpose

This candidate tests the first generic XGO libretro serialization adapter while preserving the already hardware-proven external FCEUmm launch/gameplay path.

The experiment changes only the state callback behavior:

```text
previous: xgo_core_state_io -> xgo_disabled_state_io() -> 0
candidate: xgo_core_state_io -> xgo_state_io_dispatch()
```

The frontend still installs the same single GP-safe pointer into both stock state slots. The dispatcher distinguishes the confirmed stock paths:

```text
.kmp        -> SAVE serializer prefix
.sa0..sa3   -> LOAD serializer prefix
.skp        -> LOAD (Arcade-family compatibility path)
```

Keeping one callback for the first hardware test minimizes the delta from the successful external NES build. Separate load/save veneers can be introduced after the stock path contract is confirmed on hardware.

## Generic state implementation

New source:

```text
tools/multicore/native_nes/xgo_libretro_state.c
```

SAVE path:

```text
stock .kmp scratch path
  -> retro_serialize_size()
  -> retro_serialize()
  -> stock-compatible compression helper
  -> write uint32 compressed_size + compressed bytes
  -> stock frontend continues final .saN/preview construction
```

LOAD path:

```text
stock final .saN path
  -> read uint32 compressed_size + compressed bytes
  -> ignore trailing preview metadata
  -> stock-compatible uncompress helper
  -> retro_unserialize()
```

The implementation validates allocations, lengths, compression status, file I/O, and libretro return values.

## Hardware test protocol

1. Keep the same patched `bios/bisrv.asd` that already ran the successful external FCEUmm build.
2. Replace only `/cores/fceumm/core.xgc` with this candidate.
3. Launch the same known-good Contra ROM.
4. Confirm normal gameplay/audio/input and Select+Start exit remain intact.
5. Save a visually distinguishable game state into a stock slot.
6. Confirm the slot preview appears and the final `.saN` is created/updated.
7. Resume and alter the game state.
8. Load the slot and confirm restoration.
9. After safe shutdown, inspect the card for the final `.saN` and any unexpected leftover `.kmp` scratch file.

## Pass criteria

A full pass requires:

- no regression in external FCEUmm gameplay;
- save operation accepted by stock UI;
- final `.saN` generated by stock path;
- stock slot preview remains functional;
- subsequent load restores the external FCEUmm game state;
- no persistent scratch artifact unless stock firmware normally leaves one.

## Failure interpretation

A failure should be mapped to the narrowest layer rather than treated as generic save-state incompatibility:

- gameplay regression before pause UI -> candidate runtime/link/GP regression;
- Save fails/no `.saN` -> `.kmp` callback, serialization, compression, or prefix contract;
- `.saN`/preview succeeds but Load fails -> decompression/unserialize or callback-direction issue;
- state loads but preview fails -> frontend bundle/thumbnail interaction rather than core serialization;
- stale `.kmp` remains -> stock frontend did not complete the expected post-callback path.

This candidate is intentionally designed so each observable isolates a useful boundary.
