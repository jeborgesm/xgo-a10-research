# Setup display failure: resource vs runtime separation

## BIN/SRC findings
- `XGO_Native_Setup_Handle_P1_P2_Toggle_Hardware_Test.zip` embeds six 640×480 RGB565 `Resources/*` Setup screens, generated by `SOURCE/build_xgo_native_handle_toggle.py`.
- The generated Setup screen copies the TV icon from the stock source image into top-right tile (destination x=442..600, y=30..188). The tile's caption `TV System` is copied separately to y≈192; it does **not** draw `NTSC` or `PAL` inside the icon.
- P1/P2 labels are static pixels inside HANDLE tile (x≈489 and 555, y=342), but the mode underline is dynamically drawn by firmware code at `0x80A37FA4` and reached from hook `0x80A38AB4`.
- Original native toggle hook word at `0x80A38AB4`: `0x1120FD3B`; PAL isolation restoration: `0x1120012E`. This deliberately disables dynamic underline, explaining its loss in NTSC (HW-confirmed).
- PAL/NTSC mode text is not part of the six generated bitmaps; it is a distinct runtime overlay. Its placement requires finding the original TV-mode text compositor and adjusting its position relative to the new 3×2 tile, not redrawing the bitmap alone.

## HW
- User: switching changes controller behavior; P1/P2 underline absent in NTSC after isolation; PAL/NTSC labels still misplaced. The PAL mode invisible menu issue is not resolved.

## Engineering rule
Do not disable the mode underline hook to repair PAL; restore `0x1120FD3B` first. Do not claim moving bitmap pixels alone fixes dynamic PAL/NTSC text. Identify exact overlay coordinates and PAL framebuffer stride before next candidate.
